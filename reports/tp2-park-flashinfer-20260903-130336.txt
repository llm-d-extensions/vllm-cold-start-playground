Can a 2-GPU ("TP=2") vLLM instance be paused and its GPU memory freed, using the FlashInfer communication backend?

setup: Qwen3-32B, TP=2 (tensor parallelism across 2 GPUs), forcing the FLASHINFER+PYNCCL communication backends
RESULT: pausing did NOT complete — the process got stuck and had to be killed.

What happened:
- Booted normally in 85.72s, both GPUs fully used (~79 GiB each).
- "Sleep level 1" (park the model, keep its CUDA graphs so it can resume fast) worked: 12.31s, memory dropped to ~4 GiB per GPU.
- A newer detach step (`/checkpoint_prepare`, meant to cleanly release the GPU-to-GPU communication state before checkpointing) ran fine, 0.06s.
- The actual checkpoint step (`cuda-checkpoint`, NVIDIA's tool for freezing a GPU process to 0 MiB) failed: one GPU's process reported FAILED, the other got stuck in a blocked state. Had to force-kill everything to recover.

Key takeaway: this is the same failure seen in demo-cold-start-tp2 (see that file), now confirmed under a controlled, time-bounded retry. Root cause and the full investigation are in docs/sleep-mode.md and scripts/cuda-checkpoint-ipc-matrix.py — the short version is that `cuda-checkpoint` cannot yet freeze a multi-GPU vLLM process that's actively using GPU-to-GPU communication (NCCL), regardless of which communication backend is used.
